# V3 — GeoAI Soil Intelligence Implementation Plan

> **For agentic workers:** TDD task-by-task plan mirroring the V1 plan. Steps use checkbox (`- [ ]`) syntax for tracking. Conforms to the official Technical Requirements §7 (V3 — GeoAI Soil Intelligence).

**Goal:** Extend V2 with **SAR time-series features** (multi-temporal Sentinel-1), **auxiliary optical seasonality** (Sentinel-2 NDVI/NDMI), and **climate variables** (CHIRPS/ERA5-Land), then train a **U-Net** for pixel-wise soil class + property prediction — measured against an **XGBoost/LightGBM strong baseline** on identical spatial splits, with all experiments tracked in **MLflow**.

**Core question (spec):** *Do time-series features + deep learning improve characterization over V2?*

**Architecture:** Same layered `soilgeo` package. New modules: `features/timeseries.py`, `features/climate.py`, `sar/multitemporal.py`, `models/tiling.py`, `models/gbm.py`, `models/unet.py`, `models/dataset.py`, `models/train.py`. Time-series cubes stored as **Zarr**; DL artifacts + metrics tracked in **MLflow**. SAR is the backbone; S2 contributes only NDVI/NDMI seasonal stats.

## Execution strategy (session boundaries)

V3 splits into work that runs **locally now without credentials/GPU** and work that needs **external resources**:

| Phase | Tasks | Requires | When |
|---|---|---|---|
| **A — Scaffolding** | Task 1 (config), Task 2 (env) | nothing | now |
| **B — Pure testable core** | Tasks 3–6 (timeseries, multitemporal, climate-SPI, tiling) | `soilgeo` env only (numpy/scipy) | now, TDD |
| **C — External / heavy** | Task 7 (GBM), Task 8 (U-Net), Task 9 (acquisition + pipeline), Task 10 (report) | `environment-dl`, SH/CDS creds, GPU | next session |

Phase B modules are written test-first against synthetic arrays — same pattern as V1/V2 — and need **no** new dependencies, so they run green in the existing `soilgeo` env immediately. Phase C is gated on `environment-dl` (PyTorch/XGBoost/MLflow), Sentinel Hub + CDS credentials, and a GPU.

## Phase B — Pure testable core (TDD, runs in `soilgeo` env)

### Task 3: Time-series features (V3-F1)

**Files:** Create `src/soilgeo/features/timeseries.py`, `tests/unit/test_timeseries.py`

Input: a `[T, H, W]` float32 stack of one band (e.g. VV_dB) over T dates, NODATA = -9999.

- [ ] **Step 1 — failing tests:** assert each statistic on a hand-built `[T,H,W]` array:
  - `temporal_mean/std/p10/p90` ignore NODATA along T (use nan-aware reductions)
  - `seasonal_amplitude = p90 − p10`
  - `wet_dry_delta(stack, wet_idx, dry_idx)` = mean(wet dates) − mean(dry dates)
  - all-NODATA pixel → NODATA in every output (no crash)
  - output shape `[H,W]`, dtype float32
- [ ] **Step 2:** run, verify ImportError/failures.
- [ ] **Step 3 — implement** `compute_temporal_stats(stack, nodata=-9999) -> dict[str, np.ndarray]` returning `{mean,std,p10,p90,amplitude}`; `compute_wet_dry_delta(stack, wet_idx, dry_idx, nodata)`. Use masked/np.nan reductions with `np.errstate` guards; restore NODATA where the full-T slice is invalid.
- [ ] **Step 4:** run → all pass.
- [ ] **Step 5:** commit `feat(features): per-pixel SAR/optical time-series statistics (V3-F1)`.

### Task 4: Multi-temporal speckle filter (V3-F2)

**Files:** Create `src/soilgeo/sar/multitemporal.py`, `tests/unit/test_multitemporal.py`

Quegan & Yu (2001): for a stack of T co-registered intensity images, the filtered value of image *k* at pixel *p* is
`Î_k(p) = m_k(p) · (1/T) Σ_j [ I_j(p) / m_j(p) ]`,
where `m_j` is the local spatial mean of image *j* in a window. Operates on **linear intensity**, not dB.

- [ ] **Step 1 — failing tests:**
  - constant stack in → unchanged out (filter is mean-preserving on flat data)
  - output shape == input shape `[T,H,W]`
  - variance of the temporal-ratio-filtered stack < variance of input on a speckled synthetic (speckle reduction)
  - NODATA pixels propagate
- [ ] **Step 2:** run, verify failure.
- [ ] **Step 3 — implement** `quegan_yu_filter(stack_linear, window=7, nodata=-9999)`; helper `_local_mean` via `scipy.ndimage.uniform_filter` with NODATA-aware normalization; `db_to_linear`/`linear_to_db` helpers so callers can wrap dB stacks.
- [ ] **Step 4:** run → pass.
- [ ] **Step 5:** commit `feat(sar): Quegan & Yu multi-temporal speckle filter (V3-F2)`.

### Task 5: Climate SPI-3 (V3-F3)

**Files:** Create `src/soilgeo/features/climate.py`, `tests/unit/test_climate.py`

SPI-3: rolling 3-month precip sums, fit a gamma distribution per calendar month, transform to standard-normal z-scores. (Download via `cdsapi`/CHIRPS is Phase C; the SPI math is pure scipy and testable now.)

- [ ] **Step 1 — failing tests:**
  - `rolling_sum(series, window=3)` correct length/values
  - `spi(precip_series)` ≈ 0 mean, ~1 std on a long synthetic gamma series
  - high-precip month → positive SPI; drought month → negative SPI
  - handles zeros (gamma with zero-probability mixture)
- [ ] **Step 2:** run, verify failure.
- [ ] **Step 3 — implement** `rolling_sum`, `fit_gamma`, `spi(series, scale=3)` using `scipy.stats.gamma` + `norm.ppf`, with the zero-precip mixture correction.
- [ ] **Step 4:** run → pass.
- [ ] **Step 5:** commit `feat(features): SPI-3 drought index from precipitation series (V3-F3)`.

### Task 6: Tiling + spatial-block split (V3-T1)

**Files:** Create `src/soilgeo/models/tiling.py`, `tests/unit/test_tiling.py`

- [ ] **Step 1 — failing tests:**
  - `make_tile_index(H, W, tile=256, overlap=32)` returns windows covering the raster; stride == 224; last tile clamped to edge
  - `assign_blocks(tiles, block_km, pixel_m)` groups tiles into spatial blocks
  - `split_blocks(blocks, ratios=(0.7,0.15,0.15), seed)` → no block_id appears in more than one split (V3-T1 invariant)
  - splits are deterministic for a fixed seed
- [ ] **Step 2:** run, verify failure.
- [ ] **Step 3 — implement** the three functions; tiles as `(row_off, col_off, h, w)`; block id from `(row//block_px, col//block_px)`; split groups whole blocks.
- [ ] **Step 4:** run → pass.
- [ ] **Step 5:** commit `feat(models): tile inventory + spatial-block train/val/test split (V3-T1)`.

## Acceptance Criteria (spec §7.5)

- ✅ Every DL result paired with GBM baseline on identical splits; report states whether DL is justified.
- ✅ Evaluation reported at 250 m aggregation (honest scale), not only 10 m visuals.
- ✅ A single command / documented notebook sequence reproduces the best model given fixed seeds.
- ✅ Soil behavior clusters interpreted with physical meaning (terrain/climate), not just shown.

## Risks (carried from §10)

- **R1 SoilGrids 250 m vs 10 m** → label super-resolution; dual-scale eval (V3-T5).
- **R4 spatial autocorrelation** → mandatory spatial-block splits (Task 6) for both GBM and U-Net.
- **R5 hardware** → Colab/Kaggle fallback; Zarr windowed reads; one run ≤4 GPU-hours.
